The system is a two-part automated pipeline designed to take raw, messy text generated by AI models and turn it into a perfectly formatted, dark-mode, split-screen PDF workbook optimized for solving with a pen tablet.

It handles inconsistencies in AI outputs, allows for easy human review, and automates the complex LaTeX typesetting.

Phase 1: The Front-End (HTML/JavaScript Web App)

This is the data entry and review hub. It acts as a bridge between the AI and the database.

1. Bulk Parsing & Auto-Fill

The Input: You paste raw text generated by an AI (which was prompted to act as a strict OCR scanner) into a bulk text area.

The Engine: A JavaScript function splits the massive block of text into individual questions by looking for the QUESTION: tag.

Smart Extraction: It uses Regular Expressions (Regex) to intelligently scrape metadata. It finds the GATE Year and Marks (even ignoring extra text like "Set-3"), separates the core question text, isolates code snippets (CODE:), and splits the options (OPTIONS:) into distinct A, B, C, D fields.

Diagram Detection: It actively scans the text for a [DIAGRAM_PLACEHOLDER] tag. If found, it automatically assumes the question needs an image and pre-fills the diagram filename box with the corresponding question number.

2. The 50/50 Editor Interface

Left Side (The Editor): Every parsed question generates a custom form card. This allows you to manually tweak the extracted text, fix AI typos, change the year/marks dropdowns, or assign an image extension (.png or .jpg).

Right Side (Live Preview): As you type in the editor, the right side renders a live preview of how the question will look. It uses MathJax to instantly render LaTeX math equations on the screen, making it incredibly easy to proofread complex discrete math or calculus formulas without reading raw code.

3. Data Security & Export

Auto-Save: Every single keystroke or dropdown change is saved to the browser's localStorage. If you accidentally close the tab or the browser crashes, zero work is lost.

JSON Export: Once reviewed, clicking "Export" gathers all the data from the individual UI cards, structures it into a clean list of objects, and downloads it as gate_pyq_bulk_export.json.

Phase 2: The Back-End (Python & LaTeX Compiler)

This script acts as the formatting engine. It reads the raw data and transforms it into a highly specific visual layout.

1. Data Sanitization (The Scrubbers)

Before doing any formatting, the Python script cleans the JSON data to prevent the LaTeX compiler from crashing.

Underscore Fix: It finds sequences of underscores (used by AI for fill-in-the-blanks) and converts them into proper LaTeX horizontal lines (\rule). This prevents LaTeX from panicking and assuming the underscores are missing math subscripts.

Invisible Character Scrubbing: AI models frequently insert invisible typography characters (like Em Spaces or Non-Breaking Spaces) that standard LaTeX cannot read. The script uses Regex to hunt down and convert these Unicode characters into standard spaces.

2. Dynamic LaTeX Generation

The script loops through the sanitized JSON and builds a massive string of LaTeX code:

Dark Mode: It injects \pagecolor{black} and \color{white} at the document level, and uses a custom \lstset configuration to ensure code blocks have a dark gray background.

Split-Screen Layout: It uses the \begin{multicols*}{2} environment. This forces the question text, code, options, and inline diagrams to render strictly on the left half of a landscape page. It then forces a \newpage, intentionally leaving the entire right side of the PDF completely blank so you have a dedicated scratchpad for your pen tablet.

Inline Diagrams: If a question has a diagram, the script replaces the [DIAGRAM_PLACEHOLDER] text directly with the image rendering code, placing the graphic exactly where it belongs in the flow of the text.

Adaptive Options: It checks if the option fields have text. If they do, it prints multiple-choice options. If they are empty, it prints a standard Answer: _______ line for Numerical Answer Type (NAT) questions.

3. Auto-Compilation

Once the .tex file is written, the Python script executes a system command (os.system("pdflatex...")) to run the compiler in the background. It automatically generates the final PDF workbook without requiring you to manually open a LaTeX editor like TeXstudio.
